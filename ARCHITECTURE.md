# Архитектура Remote Desktop Application

## Общий обзор

Приложение построено по архитектуре клиент-сервер с использованием TCP сокетов для передачи данных.

## Компоненты

### 1. Host (host.py) - Сервер
**Назначение**: Машина, предоставляющая доступ к своему рабочему столу

**Основные функции**:
- Захват экрана с помощью `PIL.ImageGrab`
- Сжатие изображений в JPEG формат
- Отправка изображений через TCP сокет
- Прием команд управления от клиента
- Выполнение команд мыши/клавиатуры через `pynput`

**Потоки**:
- `send_screen()` - непрерывный захват и отправка экрана
- `receive_commands()` - прием и выполнение команд

**Протокол отправки экрана**:
```
[4 байта: размер данных] + [N байт: JPEG данные]
```

### 2. Viewer (viewer.py) - Клиент
**Назначение**: Машина, подключающаяся к удаленному рабочему столу

**Основные функции**:
- Прием изображений экрана
- Отображение в Tkinter окне
- Захват событий мыши/клавиатуры
- Преобразование координат (локальные → удаленные)
- Отправка команд управления на сервер

**Потоки**:
- `receive_screen()` - непрерывный прием и отображение экрана
- Главный поток - обработка GUI и событий

**Протокол отправки команд**:
```
[4 байта: размер] + [N байт: pickle сериализованная команда]
```

### 3. Launcher (launcher.py) - GUI запуск
**Назначение**: Графический интерфейс для упрощения запуска Host/Viewer

**Функции**:
- Отображение локального IP адреса
- Настройка параметров подключения
- Запуск Host или Viewer в отдельных процессах

### 4. Config (config.py) - Конфигурация
**Назначение**: Централизованные настройки приложения

**Параметры**:
- Сетевые (хост, порт, размер буфера)
- Качество изображения (JPEG качество, масштаб, FPS)
- Визуальные (цвета интерфейса)
- Безопасность (шифрование, пароли)

## Протокол обмена данными

### Формат передачи данных
Все данные передаются с префиксом размера:
```
┌──────────────┬─────────────────┐
│ Size (4 byte)│ Data (N bytes)  │
│ Big-endian   │ Serialized data │
└──────────────┴─────────────────┘
```

### Типы команд управления

Команды сериализуются через `pickle` и имеют формат словаря:

```python
# Движение мыши
{'type': 'mouse_move', 'x': int, 'y': int}

# Клик мыши
{'type': 'mouse_click', 'button': 'left'|'right', 'pressed': bool}

# Прокрутка
{'type': 'mouse_scroll', 'dx': int, 'dy': int}

# Клавиатура
{'type': 'key_press', 'key': str}
{'type': 'key_release', 'key': str}
```

## Преобразование координат

Viewer преобразует локальные координаты в координаты удаленного экрана:

```python
# Формула
remote_x = (canvas_x - offset_x) / scale
remote_y = (canvas_y - offset_y) / scale

где:
- canvas_x, canvas_y - координаты на локальном canvas
- offset_x, offset_y - смещение изображения в canvas
- scale - коэффициент масштабирования
```

## Оптимизации

### Производительность
1. **JPEG сжатие** - снижает объем передаваемых данных
2. **Масштабирование** - можно уменьшить разрешение экрана
3. **FPS контроль** - ограничение частоты кадров
4. **Буферизация** - использование буфера для приема данных

### Будущие улучшения
1. **Дифференциальное сжатие** - передавать только изменения
2. **H.264/H.265 кодирование** - видео кодеки вместо JPEG
3. **Адаптивное качество** - динамическая настройка на основе сети
4. **Многопоточность** - параллельная обработка кадров

## Безопасность

### Текущие недостатки
- ⚠️ Нет шифрования трафика
- ⚠️ Нет аутентификации
- ⚠️ Нет проверки целостности данных

### Рекомендации для production
1. Добавить SSL/TLS шифрование
2. Реализовать систему аутентификации (логин/пароль)
3. Использовать токены доступа
4. Логирование всех подключений
5. Rate limiting для защиты от DDoS
6. Whitelist IP адресов

## Расширяемость

### Добавление новых команд
1. Определить тип команды в протоколе
2. Добавить обработку в `viewer.py` (отправка)
3. Добавить выполнение в `host.py` (прием)

### Пример: Добавление передачи файлов
```python
# В viewer.py
def send_file(self, filepath):
    with open(filepath, 'rb') as f:
        data = f.read()
    command = {
        'type': 'file_transfer',
        'filename': os.path.basename(filepath),
        'data': data
    }
    self.send_command(command)

# В host.py
def execute_command(self, command):
    if cmd_type == 'file_transfer':
        filename = command['filename']
        data = command['data']
        with open(f'received_{filename}', 'wb') as f:
            f.write(data)
```

## Тестирование

### Локальное тестирование
```bash
# Терминал 1: Запуск Host
python3 host.py
# Введите: 127.0.0.1 и порт 5555

# Терминал 2: Запуск Viewer
python3 viewer.py
# Введите: 127.0.0.1 и порт 5555
```

### Тестирование в сети
1. Убедитесь, что машины в одной сети
2. На Host узнайте IP: `ifconfig` или `ipconfig`
3. Откройте порт в файерволе
4. Подключитесь с Viewer используя IP Host

## Производительность

### Типичные характеристики
- **Задержка**: 50-200ms (зависит от сети)
- **FPS**: 15-30 (настраивается)
- **Трафик**: 1-5 Мбит/с при 30 FPS, качество 70
- **CPU**: 10-30% на захват и сжатие

### Рекомендации по оптимизации
- Для медленной сети: качество 50, FPS 15, масштаб 0.75
- Для быстрой сети: качество 85, FPS 30, масштаб 1.0
- Для больших экранов: масштаб 0.5-0.75
